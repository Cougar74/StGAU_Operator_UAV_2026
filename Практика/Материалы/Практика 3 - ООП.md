# Практическое занятие № 3. Объектно-ориентированное программирование в Python

# 1. Что такое ООП

**ООП (объектно-ориентированное программирование)** — парадигма, при которой программу строят из объектов, объединяющих **данные** (атрибуты) и **поведение** (методы).

Один из способов организовать программу — создать класс, описывающий общий тип объектов, а затем создавать конкретные экземпляры этого класса. Например, у разных собак могут быть свои клички и возраст, но общий набор действий: `sit()` и `roll_over()`.

| Термин | Простое объяснение | Пример |
| --- | --- | --- |
| **Класс** | Описание того, какими будут объекты | `Dog` |
| **Экземпляр (объект)** | Конкретный объект, созданный по описанию | `my_dog` |
| **Атрибут** | Данные, связанные с объектом | `name`, `age` |
| **Метод** | Функция, связанная с классом | `sit()` |

**Главная идея:** класс описывает общее, а каждый экземпляр хранит собственные значения атрибутов.

## 1.1. Создание класса `Dog`

Напишем класс, представляющий собаку. У неё есть **кличка** и **возраст**, а также два действия — сесть и выполнить перекат.

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def sit(self):
        print(f"{self.name} сел!")

    def roll_over(self):
        print(f"{self.name} сделал перекат!")
```

Разберём код по частям:

1. `class Dog:` объявляет новый класс. В Python имена классов принято писать с заглавной буквы, в стиле `CapWords`.
2. `def __init__(self, name, age):` — специальный метод **инициализации**, который вызывается после создания нового экземпляра. Он записывает начальные значения атрибутов.
3. `self` — ссылка на текущий экземпляр. Python передаёт её автоматически при обычном вызове метода через объект.
4. `self.name = name` и `self.age = age` сохраняют данные именно в экземпляре, а не в общей для всех объектов переменной.
5. `sit()` и `roll_over()` — методы, которые будут доступны каждому экземпляру `Dog`.

**Важно:** `__init__()` не создаёт объект самостоятельно: объект создаётся при вызове `Dog(...)`, а `__init__()` его инициализирует. Скобки после названия класса в объявлении `class Dog:` здесь не нужны.

### Почему нужен `self`

Рассмотрим две переменные: `name` — параметр метода; `self.name` — атрибут конкретного объекта. У разных экземпляров значения `self.name` могут отличаться, хотя код класса у них общий.

**Вопрос аудитории:** что произойдёт, если написать `name = name` вместо `self.name = name`? **Ответ:** атрибут экземпляра не появится; дальнейшее обращение к `my_dog.name` вызовет ошибку.

## 1.2. Создание экземпляра и обращение к атрибутам

```python
my_dog = Dog("Банди", 5)

print(f"Мою собаку зовут {my_dog.name}.")
print(f"Моей собаке {my_dog.age} года.")
```

`Dog("Банди", 4)` создаёт экземпляр класса. Переменная `my_dog` содержит ссылку на него. Выражение `my_dog.name` обращается к атрибуту через **точку**.

Пример вывода:

```text
Мою собаку зовут Банди.
Моей собаке 5 года.
```

## 1.3. Вызов методов

```python
my_dog.sit()
my_dog.roll_over()
```

Python находит методы класса и выполняет их для экземпляра `my_dog`. При вызове `my_dog.sit()` явно передавать `self` не нужно.

## 1.4. Несколько экземпляров

```python
my_dog = Dog("Банди", 5)
your_dog = Dog("Чарли", 7)

print(my_dog.name, my_dog.age)
print(your_dog.name, your_dog.age)

my_dog.sit()
your_dog.sit()
```

Оба объекта умеют выполнять одни и те же методы, но имеют **разные атрибуты**. Изменение одного экземпляра не изменяет автоматически другой:

```python
my_dog.age = 6
print(my_dog.age)    # 6
print(your_dog.age)  # 7
```

# 2. Основные принципы ООП

В учебной практике обычно выделяют четыре принципа: **наследование**, **инкапсуляция**, **полиморфизм** и **абстракция**. Разберём каждый на отдельном примере.

## 2.1. Наследование

**Наследование** позволяет создавать новый класс на основе существующего. Исходный класс называется **родительским** (базовым), а новый — **дочерним** (производным). Дочерний класс может использовать методы и атрибуты родителя и добавлять собственные.

Создадим базовый класс `Car` и его потомка `ElectricCar`.

```python
class Car:
    def __init__(self, make, model, year):
        self.make = make
        self.model = model
        self.year = year
        self.speed = 0

    def get_descriptive_name(self):
        return f"{self.year} {self.make} {self.model}"

    def get_speed(self):
        print(f"Машина едет со скоростью {self.speed} км/ч")

    def update_speed(self, new_value):
        if new_value < 0:
            print("Скорость не может быть отрицательной")
            return
        self.speed = new_value
        print(f"Новая скорость: {self.speed} км/ч")


class ElectricCar(Car):
    def __init__(self, make, model, year):
        super().__init__(make, model, year)
        self.battery = 100

    def get_battery(self):
        print(f"Заряд батареи: {self.battery}%")

    def update_battery(self, new_value):
        if not 0 <= new_value <= 100:
            print("Заряд должен быть от 0 до 100%")
            return
        self.battery = new_value
        print(f"Новый заряд батареи: {self.battery}%")


my_tesla = ElectricCar("Tesla", "Model S", 2019)
print(my_tesla.get_descriptive_name())
my_tesla.get_speed()
my_tesla.update_speed(60)
my_tesla.get_battery()
my_tesla.update_battery(85)
```

**Что важно показать:**

- В записи `class ElectricCar(Car):` класс в скобках — **родитель**.
- `super().__init__(make, model, year)` вызывает инициализацию из класса `Car`: не требуется заново описывать марку, модель, год и скорость.
- `get_speed()` унаследован от `Car`; `get_battery()` принадлежит только `ElectricCar`.
- Методы `update_speed()` и `update_battery()` проверяют допустимость новых значений.

**Исправление по сравнению с исходным примером:** в `get_descriptive_name()` используется существующий атрибут `make` (вместо отсутствующего `manufacturer`); метод `update_battery()` назван правильно и выводит `battery`, а не `speed`.

## 2.2. Инкапсуляция

**Инкапсуляция** объединяет данные и операции с ними внутри объекта и позволяет контролировать, каким способом эти данные изменяются.

Например, баланс банковского счёта нельзя без проверки произвольно уменьшать. Для этого предоставляют специальные методы.

```python
class BankAccount:
    def __init__(self, balance):
        if balance < 0:
            raise ValueError("Начальный баланс не может быть отрицательным")
        self.__balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Сумма пополнения должна быть положительной")
        self.__balance += amount

    def withdraw(self, amount):
        if amount <= 0 or amount > self.__balance:
            raise ValueError("Недопустимая сумма списания")
        self.__balance -= amount

    def get_balance(self):
        return self.__balance


account = BankAccount(1000)
account.deposit(500)
account.withdraw(200)
print(account.get_balance())  # 1300
```

В Python имя `__balance` с двумя начальными подчёркиваниями подвергается **преобразованию имени** (*name mangling*). Оно защищает от случайного обращения и конфликтов имён, но **не создаёт абсолютную приватность**, как в некоторых других языках.

**Главная мысль:** методы `deposit()` и `withdraw()` проверяют правила работы со счётом в одном месте. Если в дальнейшем изменятся условия, не придётся искать проверки по всей программе.

## 2.3. Полиморфизм

**Полиморфизм** означает, что разные объекты можно использовать через один общий интерфейс, даже если реализация поведения у них различается.

```python
class Bird:
    def fly(self):
        print("Птица летит")


class Airplane:
    def fly(self):
        print("Самолёт летит")


def make_fly(obj):
    obj.fly()


make_fly(Bird())      # Птица летит
make_fly(Airplane())  # Самолёт летит
```

Функции `make_fly()` не нужно знать, птица перед ней или самолёт. Для неё важно, что переданный объект поддерживает метод `fly()`.

В Python такой подход связан с **утиной типизацией** (*duck typing*): нас интересует доступное поведение объекта, а не обязательно его принадлежность конкретному классу.

## 2.4. Абстракция

**Абстракция** помогает выделить главные характеристики объекта и пользоваться общим интерфейсом, не разбираясь каждый раз во всех деталях реализации.

В Python для формального объявления абстрактных классов есть модуль `abc` (*abstract base classes* — абстрактные базовые классы).

```python
from abc import ABC, abstractmethod
import math


class Shape(ABC):
    @abstractmethod
    def area(self):
        pass


class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return math.pi * self.radius ** 2


circle = Circle(5)
print(f"Площадь круга: {circle.area():.2f}")

# shape = Shape()  # TypeError: абстрактный класс нельзя создать напрямую
```

**Разберём пример:**

1. `Shape` задаёт общий интерфейс: у любой фигуры должна быть операция `area()`.
2. Декоратор `@abstractmethod` помечает метод как обязательный для реализации в конкретном дочернем классе.
3. `Circle` определяет свой способ расчёта площади.
4. Нельзя создать `Shape()`, пока у него остаётся абстрактный метод. При этом экземпляр `Circle` создавать можно.

# 3. Принципы проектирования ООП

**Методология разработки** — система приёмов, правил и подходов к проектированию, созданию и сопровождению программного обеспечения. Она помогает снижать сложность, уменьшать число ошибок и делать программы удобнее для изменения.

После знакомства с классами важно понять, что **само наличие классов ещё не делает программу хорошо спроектированной**. Если один класс отвечает сразу за всё, его будет трудно проверять и расширять.

## 3.1. SOLID

**SOLID** — пять принципов объектно-ориентированного проектирования. На первом знакомстве важно понять смысл каждого, а не запоминать английские формулировки дословно.

| Буква | Принцип (английский / русский) | Основная идея |
| --- | --- | --- |
| **S** | *Single Responsibility* — единственная ответственность | У класса должна быть одна основная причина для изменения |
| **O** | *Open/Closed* — открытость/закрытость | Новое поведение предпочтительно добавлять расширением, не ломая работающий код |
| **L** | *Liskov Substitution* — подстановка Лисков | Дочерний класс должен сохранять ожидаемое поведение базового |
| **I** | *Interface Segregation* — разделение интерфейсов | Лучше несколько небольших целевых интерфейсов, чем один перегруженный |
| **D** | *Dependency Inversion* — инверсия зависимостей | Высокоуровневая логика должна опираться на абстракции, а не на конкретные детали |

### Простой пример принципа S

Допустим, класс `Report` одновременно рассчитывает показатели, сохраняет их в файл, отправляет по почте и рисует диаграммы. Тогда изменение любого из этих действий заставляет менять один большой класс.

При разделении обязанностей логика расчётов находится в `ReportCalculator`, сохранение — в `ReportExporter`, а отправка — в `ReportSender`. Это не универсальный рецепт для любой программы, но полезный пример того, зачем выделять разные ответственности.

**Вопрос аудитории:** нужно ли разбивать любой маленький класс на пять частей? **Нет.** Принципы помогают принимать разумные решения, а не усложнять программу ради формального соответствия правилам.

## 3.2. DRY

**DRY** (*Don't Repeat Yourself* — «не повторяйся») — принцип, предлагающий избегать дублирования одной и той же логики или знания в разных местах программы.

Вместо повторения расчёта в нескольких методах можно выделить одну функцию или метод.

```python
def calculate_discount(price, percent):
    return price * (1 - percent / 100)


print(calculate_discount(1000, 10))  # 900.0
print(calculate_discount(2500, 20))  # 2000.0
```

**Важно:** DRY не означает, что любые две похожие строки нужно немедленно объединять. Случайное совпадение внешнего вида кода ещё не означает, что у него одна ответственность.
